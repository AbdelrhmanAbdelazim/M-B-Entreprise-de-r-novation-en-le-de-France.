# Windsor analytics consumers — 19 October 2026

The operator confirms Search Console, GA4, Google Business Profile, Google Ads, Meta Ads and Instagram are connected in Windsor.ai. This does **not** establish that hosted n8n or this Cloud session can read them. At this release, no callable Windsor tool, Cloud Windsor binding, n8n Windsor credential/query/node or real analytics snapshot was available. No provider data read succeeded or was claimed. A deduplicated access task is stored in Growth Queue.

These Code-only patches extend the existing W5/W8/W10 IDs. They preserve every graph, native node, credential, schedule, webhook and W0 setting. `*.before.json` archives the sanitized published versions from commit `14ec299`. Exact deployed versions and access evidence are in `../../windsor-release.json`. Earlier releases remain immutable and are validated separately.

- W5 reports each source's own metrics, date window and currency, or explicitly missing/stale data. Missing does not mean zero; overlapping snapshots and source-specific conversion definitions are not summed.
- W8 uses fresh Search Console/GA4 observations to rank at most five pages already discovered on the site's homepage. Analytics cannot introduce arbitrary fetch targets. Measured low CTR can create a deduplicated review task for an existing page. No doorway pages or automatic website edits.
- W10 uses validated observations for content discovery and records their periods. All generated content still requires human approval and a separate publishing connection. Ads remain drafts with budget zero. Read access through Windsor is not publishing permission.

The pure validation boundary is `../../windsor.js`. Snapshots must be `type=analytics_snapshot`, `source=Windsor.ai`, `status=done`, with the normalized `mb.windsor.v1` contract. Captures older than 72 hours, periods ending over eight days ago, future data, invalid metrics and source identity errors are rejected/held. Only selected aggregate metrics, first-party page URLs and bounded content titles enter context. No customer identities, API keys or authenticated URLs belong in snapshots.

`../../windsor_import.py` provides a **private-export bridge**, not an automatic Windsor collector. Default execution validates offline without network; `--apply` upserts only the existing Growth Queue analytics namespace, then reads it back. Same account/window has a deterministic key, identical data is a no-op, and older data cannot overwrite newer data. Map actual Windsor field names explicitly to the normalized contract; no field aliases, account identities or connector endpoints are guessed. Never import synthetic test fixtures into production.

Required normalized fields: `schema`, `channel` (`search_console|ga4|gbp|google_ads|meta_ads|instagram`), non-secret selected `account` label, `period_start`, `period_end`, zoned `captured_at`, and numeric `metrics` from the per-channel allowlist in the importer. Optional `currency` is mandatory for cost; `pages` and `posts` are bounded aggregate dimensions. Ratios/average positions must be correctly aggregated upstream; this bridge never sums averages or overlapping periods. Keep real exports under ignored `private-live/` or another private path, never Git.

Future automatic ingestion remains blocked until the existing Windsor read connection is exposed to n8n/Cloud. After that, verify the actual selected accounts/fields and deploy a bounded scheduled reader using that connection. Do not ask for secrets in chat, create a replacement key, infer publication permissions or add paid campaigns.
